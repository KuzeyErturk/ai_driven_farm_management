## Retraining Models

```bash
python utils/train_pooled_models.py
```

This trains **pooled anomaly models** using France + UK data from the cross-country transfer research. The approach:
1. Detrends yields per (Region, Crop) to remove technology trends
2. Standardises weather to per-region z-scores to remove climate baseline differences
3. Pools France + UK anomaly data for more training samples
4. Trains Ridge regression on pooled anomalies

| Crop | Algorithm | LOOCV R² | Previous R² |
|------|-----------|----------|-------------|
| Wheat | Ridge(α=1) | 0.682 | 0.355 |
| Winter_Barley | Ridge(α=1) | 0.624 | 0.238 |
| Spring_Barley | Ridge(α=100) | 0.760 | 0.221 |
| Oats | Ridge(α=10) | 0.492 | 0.248 |
| OSR | Ridge(α=1) | 0.443 | 0.196 |

Each model uses 45 weather features internally but the UI shows 5 key features per crop. Saves `.pkl` files (model + scaler + meta) + `model_config.json` to `models/`.

The old `utils/train_improved_models.py` (UK-only, crop-specific algorithms) is kept for reference but superseded.

## Architecture

This is a demo Flask web app for UK crop yield prediction, using pooled anomaly models from the cross-country transfer research in `../src/france/`.

**Prediction flow:** Browser → `app.py` `/predict` → loads pooled model + scaler + metadata from `models/` → converts raw weather inputs to z-scores using saved UK regional stats → feeds 45-feature z-score vector through StandardScaler + Ridge → predicted yield anomaly + UK base yield → JSON response. Falls back to rule-based estimates if model files missing.

**Key files:**
- `models/model_config.json` — per-crop UI feature lists, ranges, model types, and metadata (generated by training script)
- `models/{crop}_meta.pkl` — UK weather stats (mean/std per region per feature), model feature list, base yield
- `app.py` — Flask routes; `predict_pooled_anomaly()` handles z-score conversion and anomaly prediction
- `utils/train_pooled_models.py` — training script for pooled anomaly models (France + UK data)
- `utils/predictor.py` — `CropPredictor` class (legacy, not used by current pooled model flow)
- `utils/risk_analyzer.py` — `RiskAnalyzer` class used by `/api/risk` endpoint; uses its own heuristic scoring (not the ML models)
- `utils/visualizer.py` — matplotlib chart generators

**Pages:** `index.html` (prediction form with dynamic sliders), `scenario.html` (interactive scenario analysis), `risk.html` (risk dashboard — uses legacy 8-feature heuristics)

## Data

- UK dataset: `../data/processed/regional_crop_yield_weather_2004_2024.csv`
- UK barley-specific: `../data/processed/winter_barley_with_weather.csv`, `../data/processed/spring_barley_with_weather.csv`
- France dataset: `../data/france/processed/france_regional_crop_yield_weather_2004_2018.csv`
- France barley: `../data/france/processed/france_winter_barley_with_weather.csv`, `../data/france/processed/france_spring_barley_with_weather.csv`
- 5 crops: Wheat, Winter_Barley, Spring_Barley, Oats, OSR
- UK: 4 regions (England, Wales, Scotland, Northern Ireland), France: 4 macro-regions (Nord, Ouest, Est, Sud)

## Key Design Decisions

- `model_config.json` drives both backend prediction and frontend form generation — single source of truth
- Feature sliders dynamically rebuild when crop selection changes (no hardcoded weather inputs)
- Pooled anomaly models use 45 weather features but UI shows only 5 key features per crop; non-specified features default to z-score 0 (average conditions)
- Raw weather inputs are converted to z-scores using saved per-region UK statistics before prediction
- Risk page (`risk.html`) still uses the old 8-feature WEATHER_RANGES since it has its own rule-based scoring, not the ML models
- The `models_backup_20260226_153324/` directory is a backup of original generic models
