## Retraining Models

```bash
python utils/train_improved_models.py
```

This trains crop-specific models matching the dissertation research and saves `.pkl` files + `model_config.json` to `models/`. Each crop uses its own algorithm and feature set:

| Crop | Algorithm | Features |
|------|-----------|----------|
| Wheat | RF(max_depth=8) | Area_hectares, Winter_Sun, Summer_Sun, Extreme_Summer_Rain, Grain_Filling_Rain |
| Winter_Barley | RF(max_depth=5) | Area_hectares, Spring_Tmax, Winter_Sun, Planting_Rain, Winter_Frost |
| Spring_Barley | Ridge(alpha=10) | Area_hectares, Spring_Rain, Spring_Tmax, Summer_Sun |
| Oats | RF(max_depth=3) | Area_hectares, Spring_Rain, Rain_Deviation_from_Optimal, Flowering_Sun |
| OSR | SVR(kernel=linear) | Area_hectares, Summer_Tmin, Planting_Rain, Winter_Frost |

The old `utils/train_models.py` (8 generic features, same RF for all crops) is kept for reference but superseded.

## Architecture

This is a demo Flask web app for UK crop yield prediction, aligned with the dissertation's research models in `../src/models/`.

**Request flow:** Browser → `app.py` routes → loads crop-specific `.pkl` model + scaler from `models/` → scales features → returns JSON prediction. If no model file exists, `calculate_fallback_prediction()` provides rule-based estimates.

**Key files:**
- `models/model_config.json` — per-crop feature lists, ranges, model types, and UI metadata (generated by training script)
- `app.py` — Flask routes; loads `model_config.json` at startup, serves `/api/features/<crop>` for dynamic forms, and `/predict` with proper scaling
- `utils/predictor.py` — `CropPredictor` class with crop-specific model loading and prediction (wired into app.py via config)
- `utils/risk_analyzer.py` — `RiskAnalyzer` class used by `/api/risk` endpoint; uses its own heuristic scoring (not the ML models)
- `utils/visualizer.py` — matplotlib chart generators
- `utils/train_improved_models.py` — training script for crop-specific models

**Pages:** `index.html` (prediction form with dynamic sliders), `scenario.html` (interactive scenario analysis), `risk.html` (risk dashboard — uses legacy 8-feature heuristics)

## Data

- Primary dataset: `../data/processed/regional_crop_yield_weather_2004_2024.csv`
- Barley-specific: `../data/processed/winter_barley_with_weather.csv`, `../data/processed/spring_barley_with_weather.csv`
- 5 crops: Wheat, Winter_Barley, Spring_Barley, Oats, OSR
- 4 regions: England, Wales, Scotland, Northern Ireland
- 84 observations per crop (2004-2024, 4 regions)

## Key Design Decisions

- `model_config.json` drives both backend prediction and frontend form generation — single source of truth
- Feature sliders dynamically rebuild when crop selection changes (no hardcoded weather inputs)
- Risk page (`risk.html`) still uses the old 8-feature WEATHER_RANGES since it has its own rule-based scoring, not the ML models
- The `models_backup_20260226_153324/` directory is a backup of original generic models
